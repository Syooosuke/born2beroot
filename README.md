## Description

このプロジェクトは、仮想環境上に安全なサーバーを一から構築することを目的としたプロジェクトです。パソコンやサーバーが、裏側でどのように設定されているのかを、実際に手を動かして学ぶことが目標です。具体的には、以下のようなことを自分の手で行います。
- 仮想マシン(VM)を使って、パソコンの中にもう1台のサーバーを作る
- OS(Debian または Rocky Linux)を自分でインストールし、ディスクの区画(パーティション)を適切に分割する
- 誰でも管理者権限を使えてしまう状態を避けるため、ユーザーやグループの権限を適切に設定する
- 外部からの不正なアクセスを防ぐため、ファイアウォールやアクセス制御の仕組みを導入する
- パスワードの使い回しや簡単なパスワードを防ぐための強制的なルール(パスワードポリシー)を設定する
- サーバーの状態(CPU使用率やディスク容量など)を定期的に自動で記録する仕組みを作る

上記の項目を通して、ネットワーク上に安全なサーバー環境を構築し、システム管理の基礎(OSインストール、セキュリティ設定、ネットワーク設定など)を学ぶことを目的としています。

このプロジェクトにおいて、サーバー用のLinuxディストリビューションとして**Debian**を採用しました。理由は以下の比較の通りです。

---
### Debian vs Rocky Linux

DebianとRocky Linuxは、どちらもLinuxをベースにしたOSであるものの、開発の背景や想定している使い道が異なります。

Debianは1993年から続く歴史の長いディストリビューションで、特定の企業に属さず、コミュニティによって開発が続けられています。個人のサーバー構築や学習用途でよく使われており、無料で使える範囲が広いのが特徴です。

一方Rocky Linuxは、企業向けOSであるRed Hat Enterprise Linux(RHEL)と互換性を持つように作られたディストリビューションです。もともとCentOSというOSがこの役割を担っていましたが、開発方針の変更をきっかけに、その後継としてRocky Linuxが2021年に登場しました。企業の業務システムなど、RHELを前提にした環境で使われることが多いです。

| | Debian | Rocky Linux |
|---|---|---|
| 開発体制 | コミュニティ主導 | Rocky Enterprise Software Foundationが運営 |
| 主な用途 | 個人サーバー、学習、幅広い用途 | 企業システム、業務用サーバー |
| ソフトウェアの更新頻度 | 安定性重視のため、比較的古いバージョンで固定されやすい | Debianと同程度だが、企業向けの更新サイクルに合わせている |
| 商用ソフトとの相性 | 特に想定されていない | 良い(業務用ソフトはRHEL系を前提にしていることが多い) |

**メリット・デメリット**

- **Debian**
  - メリット:情報や解説記事がネット上に非常に多く、個人利用や学習用途で困ったときに調べやすい
  - デメリット:企業向けの有償サポートが用意されておらず、トラブル対応は自力で行う必要がある

- **Rocky Linux**
  - メリット:企業で広く使われているRHELとほぼ同じ動作をするため、実務に近い環境で学べる
  - デメリット:登場してからまだ数年しか経っておらず、Debianに比べると情報量が少ない

### 🛡️ AppArmor vs SELinux(アプリを「檻」に入れて守る仕組み)

**そもそも何のためのもの?**
たとえ悪意のあるプログラムやバグのあるプログラムが動いてしまっても、「このアプリはこのファイルにしかアクセスできない」というルールを事前に決めておくことで、被害を最小限に抑える仕組みです。家の中に金庫を置いて、鍵を持っている人しか開けられないようにするイメージです。

| | AppArmor | SELinux |
|---|---|---|
| 標準搭載OS | Debian, Ubuntu | Rocky Linux, RHEL |
| ルールの決め方 | 「このファイルパスは触ってOK/NG」という分かりやすい指定 | 「ラベル」という目印を全てのファイル・プロセスに貼り、ラベル同士の相性でアクセスを判断(仕組みが複雑) |
| 難易度 | 易しい | 難しい |
| 守りの強さ | そこそこ強い | 非常に強い |

**メリット・デメリット**

- **AppArmor**
  - 👍 メリット:設定がシンプルで、初心者でも理解しやすい
  - 👎 デメリット:SELinuxほど細かい制御はできない

- **SELinux**
  - 👍 メリット:非常に細かくアクセス制御ができ、セキュリティレベルが高い
  - 👎 デメリット:仕組みが複雑で、原因不明のエラー(「なぜか動かない」)に遭遇しやすく、初心者はつまずきやすい

### 🔥 UFW vs firewalld(ネットワークの「門番」)

**そもそも何のためのもの?**
サーバーへの通信のうち、「許可された通信だけ通す、それ以外は全部拒否する」という門番のような役割です。マンションの入口にいる警備員が、名簿にある人だけ中に入れるイメージです。

| | UFW | firewalld |
|---|---|---|
| 標準搭載OS | Debian, Ubuntu | Rocky Linux, RHEL |
| 正式名称 | Uncomplicated FireWall(「複雑じゃないファイアウォール」という意味) | firewall daemon |
| 設定方法 | 「22番ポートを許可する」のようにシンプルなコマンド1行で完結 | 「ゾーン」という単位で通信ルールをグループ分けして管理(自宅用・社内用・公開用、など細かく分けられる) |
| 設定変更の反映 | 一部再起動が必要な場合がある | 再起動せずにすぐ反映される |

**メリット・デメリット**

- **UFW**
  - 👍 メリット:コマンドが直感的で覚えやすく、すぐに使い始められる
  - 👎 デメリット:複雑なネットワーク構成(用途ごとに細かくルールを分けたい場合など)には向かない

- **firewalld**
  - 👍 メリット:ゾーンごとに柔軟なルール設定ができ、企業の複雑なネットワークにも対応できる
  - 👎 デメリット:「ゾーン」や「サービス」といった概念を覚える必要があり、最初のハードルがやや高い

### 💻 VirtualBox vs UTM(仮想マシンを動かすソフト)

**そもそも何のためのもの?**
自分のパソコン(Windows/Mac)の中に、もう一台別のパソコン(仮想マシン)を作り出すソフトです。この「仮想マシン」の中にDebianやRocky Linuxをインストールして、実機を用意しなくても自由に試したり壊したりできるようにします。

| | VirtualBox | UTM |
|---|---|---|
| 開発元 | Oracle社 | オープンソースコミュニティ |
| 得意なパソコン | Windows、Intel搭載Mac | Apple Silicon搭載Mac(M1/M2/M3など) |
| 対応の広さ | 昔からあり情報が豊富 | Macでの利用に特化 |

**メリット・デメリット**

- **VirtualBox**
  - 👍 メリット:歴史が長く、Windows・Intel Macでの実績が豊富で情報も見つけやすい
  - 👎 デメリット:Apple Silicon(M1以降のMac)では動作が不安定になることがある

- **UTM**
  - 👍 メリット:Apple Siliconに最適化されており、Mac上で軽快に動く
  - 👎 デメリット:Windows/Intel系のパソコンでは選択肢にならず、機能面ではVirtualBoxよりシンプル
